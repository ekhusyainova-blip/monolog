# PRINCIPLES — принципы построения кода Monolog

Предварительный набор. Дополняется по ходу разработки.

---

## 1. Уровень кода

- Файл — одна ответственность.
- Файл ≤ 200 строк. При росте — разбивать.
- Один модуль = один экспорт-набор (роутер, функции, класс).
- Не использовать глобальное состояние без необходимости.
- Асинхронные функции по умолчанию (`async def`).
- Все исключения — явные, с понятным сообщением.

---

## 2. Уровень модулей

- Модуль самодостаточен: работает без других модулей своего уровня.
- Модуль не импортирует другие модули того же уровня (роутер не импортирует роутер).
- Модуль импортирует только:
  - `config` — константы и env
  - `storage` — доступ к хранилищу (когда появится)
  - `contracts` — типы и протоколы (когда появятся)
  - стандартную библиотеку и сторонние пакеты
- Модуль регистрируется в `routers/` — автосканирование подхватит.
- Модуль не знает, кто его вызвал.

---

## 3. Уровень контрактов

- Каждый модуль предоставляет чёткий интерфейс.
- Функции принимают понятные аргументы, возвращают понятный результат.
- Никогда не возвращать разные типы в одной ветке (str или None — валидно; str или dict — нет).
- Исключения — часть контракта.
- Контракт документируется в docstring.

---

## 4. Уровень сборки

- Триггеры — данные, не код.
- Включение модуля — через переменные окружения (env).
- Примеры триггеров:
  - `APP_MODE=stub|full`
  - `STORAGE_TYPE=github|local|s3`
  - `LLM_PROVIDER=groq|openrouter|...`
  - `FEATURES=chat,public,code,ai_apply`
- Новый модуль добавляется — и всё.
- Новый триггер добавляется — и всё.
- Никаких правок в основном коде, только в конфиге.

---

## 5. Уровень инфраструктуры

- Код не знает, где он работает.
- Dockerfile универсален: Render, свой VPS, локальный ПК.
- Все внешние сервисы — за адаптерами.
- `storage` — фасад над GitHub / локальной папкой / S3.
- Переезд между вариантами = смена env, а не кода.
- Клиент выбирает вариант: GitHub+Render / свой ПК / облако / гибрид.

---

## 6. Принципы разработки (по ходу)

- Маленькие доработки патчами.
- Каждый патч — отдельный файл или правка одного места.
- Не ломать работающее.
- Проверять после каждого шага.
- Не увеличивать сложность без необходимости.
- Фиксировать принципы по ходу — этот документ живой.

---

## 7. Принципы взаимодействия (Monolog)

- Код — инструмент. Цель — Человек.
- Не вести. Отражать.
- Не решать за человека.
- Не выдумывать восприятие.
- Ядро — то, что делает фрагменты целым.
- Целостность — цель системы.
