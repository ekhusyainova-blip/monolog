# MODES — режимы работы, доступ, устойчивость Monolog

Рабочий документ. Дополняется по ходу. Версия 0.2 (2026-09-17).

---

## 1. Режимы работы

Пять режимов. Переключаются в UI и командой в чате.

| Режим | Кто решает | Кто действует | Когда |
|---|---|---|---|
| **AUTO** | Monolog | Monolog | Промпты стабильны |
| **CONFIRM** | Monolog предлагает | Monolog после подтверждения | Промпты нестабильны |
| **MANUAL** | Пользователь | Monolog по команде | Полный контроль |
| **RAW** | Пользователь | Monolog сохраняет, не анализирует | Вставка кода вручную |
| **OFF** | — | Никто | Monolog спит |

По умолчанию — **CONFIRM**.

Переключение: в UI (селектор) или командой в чате.

---

## 2. Инструменты (внутренние)

Доступны, когда backend работает.

| Эндпоинт | Что делает |
|---|---|
| `POST /chat` | общение |
| `POST /ai/apply` | сохранить файл (JSON body) |
| `POST /ai/apply_raw` | сохранить файл (text/plain body) |
| `GET /code/read` | прочитать файл |
| `POST /code/save` | сохранить в ветку CODE_BRANCH |
| `GET /code/check` | проверить синтаксис одного файла |
| `GET /code/diagnose` | проверить все .py файлы |
| `GET /public/*` | публичные данные |

Планируется:

- `POST /code/copy_branch` — копировать main ↔ dev
- `POST /code/create_branch` — создать новую ветку
- `GET /code/export` — выгрузить репо

---

## 3. Аварийный доступ (внешний)

Когда backend не запускается — внутренние инструменты недоступны.

Внешние точки доступа:

1. **GitHub-веб** — работает всегда. Искажает файлы >80 строк. Значит: только для коротких правок.
2. **Второй сервис** — если `main` сломан, работаем из `dev`. Если `dev` сломан — из `main`. Симметрично.

Внешний редактор — **не используем**.

---

## 4. Два сервиса: main и dev

Оба на Render. Оба подключены к одному репозиторию, разным веткам.

| Сервис | Ветка | URL |
|---|---|---|
| ai-monolog | main | ai-monolog.onrender.com |
| agent-23r6 | dev | agent-23r6.onrender.com |

**Взаимное управление:**

- Из main-сервиса можно писать в `dev` (через `CODE_BRANCH=dev`).
- Из dev-сервиса можно писать в `main` (через `CODE_BRANCH=main`).
- Реализуется через GitHub API с параметром `ref`.

**Сценарий восстановления:**

1. main сломан.
2. Заходим на dev-сервис.
3. Через dev читаем/пишем в ветку `main`.
4. Исправляем.
5. Render передеплоит main.
6. main оживает.

Симметрично — наоборот.

## 6. Создание веток

**Зачем:**

- Эксперименты, не трогая main.
- Тесты.
- Временные правки.

**Как:**

- `POST /code/create_branch` — параметры: `name`, `from_branch`.
- Или через GitHub-веб вручную.

---

## 7. Правила устойчивости

- **`app.py` ≤ 100 строк** — перезалив через GitHub-веб.
- **Роутеры ≤ 200 строк** — GitHub-веб не искажает.
- **Модули автономны** — падение одного не блокирует остальные.
- **`APP_MODE=stub`** — всегда доступен.
- **`storage`** — с локальной опцией (когда появится).
- **Два сервиса** — main и dev.
- **Коммит после каждого действия** — откат по истории.

## 10. Принципы автономного модуля

Модуль — это **самостоятельный блок**. Монтируется куда угодно. Не зависит от других модулей того же уровня.

**Правила:**

- **Одна ответственность** — один модуль, одна задача.
- **Автономность** — модуль работает без других модулей своего уровня.
- **Изоляция импортов** — модуль импортирует только:
  - стандартную библиотеку,
  - сторонние пакеты (fastapi, httpx и т.п.),
  - `config` (константы, env),
  - `storage` (когда появится) — фасад над хранилищем,
  - `contracts` (когда появятся) — типы и протоколы.
- **Никаких импортов других роутеров** — роутер не знает о роутере.
- **Монтирование через контейнер** — UI-модуль получает `container` и разворачивается в нём. Не знает, sheet это, страница или модал.
- **Свои стили** — модуль приносит свой `module.css`, не правит общий `adaptive.css`.
- **Свой бэкенд-роутер** — если модулю нужен backend, он создаёт файл в `routers/`. Автосканирование его подхватит.
- **Конфиг — данные, не код** — включение/выключение модуля через env (триггер), а не правку кода.
- **Обновление отдельно** — можно обновить один модуль, не трогая остальные.
- **Удаление без последствий** — если модуль убрать, остальные продолжают работать.

**Пример:**

Модуль «Редактор файлов GitHub»:

- backend: `routers/editor.py` (при необходимости) — эндпоинты для чтения/записи/проверки.
- frontend: `adaptive/editor/editor.js` + `adaptive/editor/editor.css` — UI, монтируется в переданный контейнер.
- подключается любым способом: кнопка, sheet, страница, отдельное окно — как решит вызывающая сторона.
- ничего не знает про «пакеты», «продукты», «страницу разработки» — это отдельные модули.

- Для тестов.

- Ветка создаётся как копия base-ветки.

**Что даёт:**

- Можно экспериментировать без риска.
- Можно вернуться к стабильному main.
- Можно параллельно разрабатывать разные фичи.

- **Все модули автономны** — падение одного не блокирует остальные.
